# 冷却流路 概念設計ソルバ (coldplate v2)

[<- リポジトリ README](../../README.md) | **セッション引き継ぎ → [HANDOVER.md](HANDOVER.md)**

**注意**: 本ディレクトリは xkep-cae-fluid 本体 (FDM/FVM ソルバー・Process Architecture)
とはほぼ独立した実験タスク。CI 対象外で、追加依存に torch を使う
(`pip install torch` が別途必要)。

## 概要

格子グラフ上の回路方程式 (Hagen-Poiseuille + Kirchhoff) と鮮度スカラー輸送で、
発熱体アレイ (4×8) に対する冷却流路レイアウトを秒〜分オーダーで生成する
「エセトポロジー最適化」(ground structure 法 + SIMP)。
定式化・較正パラメータ・踏んだ罠は `coldplate.py` 冒頭 docstring と
引き継ぎメモ (会話ログ) を参照。

## v2 での修正 (v1 からの差分)

### P0: 「孤立している流路にも液が流れる」偽解の排除

v1 は SIMP の `rho_floor = 1e-4` により、消したはずの辺にも
`g = rho_floor^p · w^4 / L > 0` の伝導度が残り、Kirchhoff 解が全域に微小流を
配っていた。節点レベルの質量保存 `div q = b` 自体は破れていない
(体積保存「制約」の問題ではなく、**ゼロであるべき辺に流れが乗る**モデル構造の問題)。
この漏れ流れが除熱の得点として目的関数に混入し、`connectivity_check() = False`
の分断解が最適に見えていた。小規模検証では総流量 Q=1 に対し
`rho<0.5` の辺が計 1.38 の |q| を運んでいた (`leak_inactive`)。

対策 (引き継ぎメモ P0-(a) の実装 = 逐次刈り込み):

1. `prune()` — `rho > 0.5` (不成立なら閾値を段階的に緩和) の辺で連結成分を取り、
   inlet/outlet の重みを両方含む主成分だけを残す。さらに厳密再解して
   `|q| < 1e-6·Q_tot` の死枝 (無流量のヒゲ・孤立リング) を除去。
2. `decode(mask=...)` — 主成分外の辺は **rho = 0 (厳密ゼロ)**、主成分内は
   **rho = 1** に凍結。ポート softmax も主成分内に制限 (自動再正規化)。
3. `physics(edge_on=...)` — アクティブ節点のみで Kirchhoff を解く。
   凍結辺は g = 0 なので流量は**厳密にゼロ** (数値ノイズすらない)。
4. `optimise(mask=...)` — 凍結位相の上で幅 w とポート配分を再最適化。
5. 1-4 を マスクが安定するまで反復 (`solve_pipeline`, 既定 3 ラウンド)。

検証 (`mass_check`):

- `resid_max` — 節点質量残差 max|div q − b| → 1e-9 以下
- `leak_inactive` — 凍結辺の流量合計 → **厳密に 0.0**

### P1: grey (中間 rho) の排除

- stage A で penal 1→2→3 / softmin β 4→6→8 / mu_bin 0.3→1→3 の continuation
- 刈り込み後は rho ∈ {0, 1} に凍結するため **grey = 0 が構造的に保証**される

### 均一性

- ブロック別除熱の `block_cv` (変動係数)・`block_min_over_mean` を `report()` に追加
- 刈り込み後ラウンドは softmin β = 12 に強化して worst ブロックを直接押し上げ
- v1 の「不均一に見える流れ」の一因は漏れ流れの得点混入 (見かけの除熱が
  分断領域にも付く)。厳密ゼロ化後の数字が設計間比較に使える値
- 追加の均一性罰則 `Config.mu_uni` (ブロック別 log 除熱の分散) をオプションで用意

## 実測結果 (フル問題 18×29, 997 辺, 32 ブロック)

散逸上限 `log_p_max` の比較 (`run_compare.py`, ログは `logs/` 参照):

| | raw SIMP (v1 相当) | v2 cap=5.0 | v2 cap=3.5 (推奨) |
|---|---|---|---|
| 漏れ流量 (存在しない辺の Σ\|q\|) | **6.70** (Q_tot=1 比 670%) | 0.0 (厳密) | 0.0 (厳密) |
| 給水網の連結性 | **False** (2 成分に分断) | True | True |
| ブロック被覆 | 32/32 (うち多数が漏れ頼み) | 29/32 | **32/32** |
| worst-block 除熱 (log) | -4.75 (偽値: 漏れ得点混入) | -5.26 | **-5.14** |
| block_min/mean | 0.71 (偽値) | 0.51 | **0.66** |
| grey | 8.4% | 0% | **0%** |
| 実効ポート数 in/out | 1.3 / 2.5 | 1.6 / 2.6 | **4.8 / 3.3** |

- 引き継ぎメモの「log_p_max を 3.5 に絞ると清潔な解」を定量確認。緩い上限 (5.0)
  では漏れ経由で「冷えたフリ」をする分断構造が育ち、刈り込み時に 3 ブロックが
  孤児化する。**3.5 + v2 刈り込みで全ブロック被覆・漏れ厳密ゼロを両立**。
- inlet 分散 (実効 4.8 ポート) / outlet 比較的集中という引き継ぎの知見も再現。
- `mu_uni=0.5` (均一性罰則) は CV 0.30→0.22 に改善するが worst-block が
  -5.14→-5.33 に悪化 (max-min 目的とのトレードオフ)。デフォルトは 0。
- raw の cooling 値は漏れ得点が混入した偽値であり設計間比較に使えない
  (引き継ぎメモ §4 の注意どおり)。比較には必ず v2 (刈り込み後) の値を使うこと。

## single-port モード (物理ポート in/out 各 1 箇所)

実機ではポートは各 1 箇所しか作れないため、分配は流路パターン (ヘッダ木) で
実現する必要がある。`solve_pipeline(single_ports=True)` で強制できる:

1. stage A で `mu_conc` を 0 → 0.5 → 2.0 にランプしてポートを自然に寄せる
2. 刈り込み時に重み最大の inlet / outlet 各 1 節点へ one-hot 凍結
   (1 要素 softmax = 厳密 1、`b` は 2 節点のみ非ゼロ)
3. 以後の再最適化で幅とヘッダ木構造が分配を担う

フル問題の散逸上限スイープ (`run_single_port.py`):

| log_p_max | 被覆 | worst-block | block_min/mean | log_diss |
|---|---|---|---|---|
| 3.5 (分散型と同条件) | **17/32** | (-4.95 ※) | 0.45 | 4.18 |
| 4.5 | 28/32 | (-4.95 ※) | 0.61 | 4.05 |
| 5.5 | **32/32** | **-5.04** | 0.61 | 4.35 |

※ cooling (softmin) は被覆ブロック数が異なると比較不能 (少被覆ほど有利に出る)

**結論: 単一ポートの代償は除熱性能ではなくポンプ動力。**
全 32 ブロック被覆時の worst-block 除熱は分散型 (-5.14) より単一ポート
(-5.04) の方がむしろ良いが、必要散逸が log 3.51 → 4.35、
すなわち**約 2.3 倍のポンプ動力**を要求する。散逸上限を分散型と同じ 3.5 に
絞ると単一ポートでは 17/32 ブロックしか届かない。
最適ポート位置: inlet は左辺上半分 (j≈19-22)、outlet は左辺下端 (j≈1-3)。
これは分散型の「inlet 上半分に分散 / outlet 下端集中」と同じ構造で、
ヘッダ木がその分配を単一ポートから再現している。

## 境界任意ポート + 空間均一化 (run_uniform.py)

設定: inlet/outlet を全境界節点 (90 候補) から各 1 箇所選択 (`port_side="boundary"`,
`single_ports=True`)、散逸上限 5.5。均一化罰則は `mu_vu` (流速 CV²) と
`mu_phiu` (発熱体位置 φ のブロック間分散)。

**重要な設計判断**: 均一化罰則を stage A (位相探索) から掛けると探索が
不安定化し被覆が 28→14 ブロックに崩壊、φ 分散もむしろ悪化する (実測、
`log-uniform-1786081022.log`)。罰則は**位相凍結後の stage B のみ**に適用する。

同一位相 (28/32 被覆、inlet=(17,18) 右上 / outlet=(0,2) 左下) での比較:

| | baseline | mu_vu=2, mu_phiu=25 | mu_phiu=100 のみ |
|---|---|---|---|
| 流速 CV | 0.89 | **0.73** | 1.02 |
| φ_block std | 0.142 | 0.149 | 0.133 |
| φ_block range | [0.29, 0.83] | [0.28, 0.83] | [0.30, 0.83] |
| worst-block | **-4.81** | -4.88 | -4.88 |

知見:

1. **流速の空間均一化はサイジングで可能** (CV 0.89→0.73)。代償は worst-block
   除熱の僅かな悪化 (-4.81→-4.88)。
2. **φ の空間均一化はサイジングではほぼ不可能** (std 0.142→0.133 が限界、
   罰則を 4 倍にしても)。φ 分布は経路長構造 = 位相で決まる。幅の自由度が
   実質死んでいる (§幾何の前提) 上、NTU への寄与も w^-0.25 と弱いため。
3. **ポートを境界自由にすると対角 (Z 型/カウンターフロー) 配置が自発的に
   選ばれる** (inlet 右上・outlet 左下)。これは各行の経路長を揃える古典的
   マニホールド構成で、位相レベルの φ 均一化の方向と一致する。
4. 単一ポート・固定流量では総鮮度収支 Σq_heat = Q·(1-φ_out) は固定であり、
   上流→下流の φ 勾配自体は消せない。φ_b を完全均一化するには全ブロックへ
   等 NTU 経路 (H 木状の等長分岐) が必要で、これは位相制約として課すか
   P0-(c) の整数計画で扱う領域。
5. 境界自由ポートの位相探索は 28/32 被覆の局所解に留まる (孤児 = 最上段行
   4 ブロック)。下記の被覆修復 (stage C) で 32/32 に回復する。

### 被覆修復 (stage C, `repair_coverage`)

刈り込み後に孤児ブロックが残る場合、貪欲 Steiner 増強で主成分に組み込む:
footprint 4 辺を有効化し、対角 2 隅からアクティブ集合へ辺素の最短回廊を
BFS で 2 本追加 (着地点が同一節点だと循環ゼロのぶら下がりループになるため
2 本目は別着地点を強制)。続く再最適化で softmin が孤児を含むようになり、
回廊へ実流量が配られる。

実測 (境界 Z 型、cap=5.5): 最上段行 4 ブロックに各 2 回廊 → **32/32 被覆**、
漏れ厳密ゼロ・connected 維持。worst-block は -4.81 (28 ブロック時) →
-5.24 (32 ブロック、修復後) — 上段行への給水は高くつくが、被覆は構成的に
保証される。なお全被覆同士の比較では左辺単一ポート解 (-5.04, log_diss 4.35)
が境界 Z 型+修復 (-5.24, log_diss 4.33) より優位であり、Z 型対角は
「経路長は揃うが上段が遠い」局所解である点に注意。

### 2 列 × 4 行 長方形配置 (run_rect24.py)

4×8 の境界 Z 型で見られた「修復回廊の継ぎ接ぎ」はアレイのアスペクト比が
原因で、2×4 では単一ポート+対角配置が自然なマニホールド木になる。
cap 掃引 (3.0 / 4.0 / 5.0)、被覆優先で cap=4.0 を採用:

| cap | 被覆 | worst | min/mean | 流速CV | 備考 |
|-----|------|-------|----------|--------|------|
| 3.0 | 8/8 (修復) | -6.05 | 0.13 | 0.85 | 動力予算不足で回廊に流量が回らない |
| 4.0 | 8/8 (修復) | -3.95 | 0.89 | 0.46 | 採用。per-block 除熱 [0.021-0.031] |
| 5.0 | 8/8 (修復不要) | -4.02 | 0.80 | 0.30 | 素の位相だけで全被覆 |

ポートは再び対角カウンターフロー (inlet 右中央 / outlet 左上) が自発的に
選ばれる。均一化 (mu_vu=2) で流速 CV 0.46→0.37、φ 分散は不変 (位相支配)。
被覆には「幾何 (回廊)」と「動力予算 (cap)」の両方が必要という構図。

## 固体伝熱レイヤー (mode="thermal", run_thermal.py)

同一格子の 2 レイヤー目として固体熱回路網を解き、目的関数を鮮度スカラーから
**発熱ブロック温度の smooth-max (ピーク温度) + 分散罰則 (温度均一化)** に
置き換えるモード。液側は近似式で扱う:

- 固体伝導: 全格子辺に G_s = k_s·t_plate / L (流路彫込は無視、Al 6061 t=3mm)
- 対流伝達: h = Nu·k_f/D_h (層流一定 Nu=3.66、D_h は矩形流路の水力直径)、
  G_cv = rho·h·(w+2d)·L (濡れ面 = 底面+側壁 2 面)
- 流体温度: 風上 1D エネルギー収支 (cp·ṁ·ΔT = 対流受熱)、inlet 基準の上昇分

(T_s, T_f) を 1 つの 2N×2N 線形系にまとめて解くため autograd がそのまま通る
(勾配検証 3e-7)。定常収支 Σ発熱 = 出口エンタルピー流束は 1e-9 で成立し、
出口温度は厳密に T_ref = ΣQ/(cp·ṁ) になる (テストで検証)。

実測 (2×4、境界単一ポート、cap=4.0、水 5 g/s、10 W/block、T_ref=3.83 K):

| ケース | T_peak [K] | T_std [K] | 被覆 | 流速CV | 特徴 |
|--------|-----------|-----------|------|--------|------|
| fresh (φ目的) | 39.6 | 1.12 | 8/8 (修復) | 0.48 | 疎な一筆書き 71 辺 |
| thermal (ピークT) | 27.3 | 0.66 | 8/8 (修復不要) | 0.87 | 密なラダー網 107 辺 |
| t-unif (+分散罰則) | 27.3 | 0.63 | 8/8 (修復不要) | 0.91 | 分散 -5% (サイジング余地小) |

**温度目的は位相を根本的に変える**: φ 目的の疎な一筆書きに対し、温度目的は
細い流路を密に張り巡らせて板全体を覆う (ピーク温度 -12.3 K / -31%)。
伝導が全ブロックへ勾配を届けるため stage A だけで 8/8 被覆に達し、修復も
block_on 除外も不要になる — P4 (伝導スプレッディング未モデル化) と
被覆保証の両問題が温度定式化では同時に解消する。一方 φ と同様、位相凍結後の
サイジング余地は小さく、分散罰則の追加効果は僅か (std 0.66→0.63)。

**w ロジット再中心化**: stage A の体積制約が幅ロジットを飽和させ (全辺
w=d_min)、位相凍結後に sigmoid 勾配が死んでサイジングが一切動かない現象を
実測 (mu_tvar=10 でもビット単位で同一解)。初回凍結時にロジットを ±2 に
クリップして勾配を復活させる修正を solve_pipeline に追加。

## 擬3D ダルシー則モデル (darcy.py, run_darcy.py)

ネットワークモデルの層流一定 Nu 近似では h が流速非依存になり「濡れ面積が
唯一のレバー」という結論しか出ない (本質が近似に隠れる)。そこで近似式を捨て、
同一形状を独立の連続場モデルで解き直す:

- **流れ**: Hele-Shaw 深さ平均のダルシー則 (K_open = t_chan²/12)。
  細分セル 1.25mm の FVM で ∇·(K t/μ ∇p) = 0 を解く
  (左辺中央 5mm 流入・右辺中央 5mm 流出、p=0 Dirichlet)。
- **設計変数**: セルごとではなく **5mm 設計ブロックごとのダルシー係数**
  (セル単位だと枝状の奇妙な最適解が出るため)。0/1 位相ではなく連続な
  透過率場 K ∈ [K_open·1e⁻⁵, K_open] を対数補間 K(s) = K_open·(1e⁻⁵)^s で
  直接設計する。物理的にはブロックごとのピンフィン密度グレーディングに相当。
- **熱**: z 方向 2 層の擬 3D。ベース板 (伝導 + 発熱入力) と流路層
  (ダルシー面流束の風上移流 + k(s) 面内伝導) を半厚み伝導の直列
  コンダクタンスで層間結合。**Nu 相関は使わない**。
- **線形系**: スパース LU (splu) を adjoint 付き autograd.Function でラップ
  (勾配 FD 照合 2e-7)。質量保存 1e-15、エネルギー収支 1e-13。

2 目的は重み付き和 J = J_T + γ·ΔP/ΔP_ref (J_T = 温度 smooth-max + 分散) を
γ スイープしてパレートフロントを得る。

実測 (2×4、水 5 g/s、10 W/block、ΔP_ref = 全開 16.2 Pa、T_ref = 3.83 K):

| ケース | ΔP [Pa] | T_peak [K] | T_std [K] | 平均固体度 | 特徴 |
|--------|---------|-----------|-----------|-----------|------|
| 全開 (一様 K_open) | 16.2 | 41.4 | 1.42 | 0 | 中央をショートサーキット |
| γ=10 | 26.4 | 8.9 | 0.21 | 0.04 | ごく薄い抵抗勾配のみ |
| γ=1 | 29.1 | 7.5 | 0.10 | 0.06 | 中央経路に緩い抵抗 |
| γ=0.1 | 44.5 | 6.3 | 0.11 | 0.13 | E 字型の分配抵抗 |
| γ=0.01 | 117.3 | 5.9 | 0.11 | 0.25 | 蛇行バッフル構造 |

**主要な知見**:

1. **全開一様場が圧倒的に悪い** (T_peak 41.4 K): 流れが in→out の中央直線に
   ショートサーキットし、上下の発熱体に冷媒がほぼ届かない。
2. **+10 Pa (1.6 倍) で T_peak が 41→9 K に激減** (γ=10): ショートサーキット
   経路にわずかな透過率勾配を付けて流量を横に配るだけで、移流が全発熱体に
   届く。ネットワーク+一定 Nu では見えなかった「流速分布そのものの価値」が
   このモデルでは支配的に現れる。
3. パレートは急峻な L 字: 温度は γ=10→0.01 で 8.9→5.9 K しか下がらないのに
   圧損は 26→117 Pa に増える。実用設計は膝 (γ≈1) 付近が妥当。

**差分可視化 (run_darcy_diff.py)**: γ 4 ケースの差は全開を含む共通スケールでは
潰れて見えないため、全開を除いた差分表示を別図 (`coldplate_darcy_diff.png`) で
生成する — K 場は各パネル自動スケール、流速は対数カラー共通、温度は 4 ケース
共通のタイトスケール、加えて γ=10 基準の ΔT_s マップ。npz の設計場から前進解
のみ再計算 (再最適化なし)。

**0/1 位相化の試行錯誤 (失敗記録)**: 当初 RAMP + β 射影で 0/1 トポロジーを
狙ったが、(a) α_max 固定だと中間 θ の圧損が爆発して全開の自明解に潰れる、
(b) α_max 継続 + グレー罰則でも「θ̄≈0.5 の漏れ壁」(2値化で消える壁) を悪用した
見かけの最適解が残り、2値化後 T_peak が 15→39 K に劣化した。ユーザー指定は
「ブロックごとのダルシー係数を変数にする」なので連続場設計に切り替えて解消。

## ピンフィン物理モデル (pin_fin=True, run_pinfin.py) — HANDOVER Task 1

旧 logK モデルの s=1 は「流れを止める固体 = 良伝導体」で、流路を塞ぐ壁が
そのまま熱橋になる非物理な状態だった。さらに層間結合が線形混合 k_c(s) を
層厚伝導に使うため、少量の固体でも「流体温度へ直結する垂直伝導スラブ」と
なり U'' が一桁楽観 (s=0.17 で 22,700 W/m²K) だった。

s をピン充填率 φ = phi_max·s (既定 φ_max=0.6, d=1mm) と解釈して物理を閉じる:

- **K(φ)**: 1/K = 1/K_plate + 1/K_pin。平行平板 Hele-Shaw (t²/12) と正方配列
  円柱横断流 (Gebart 1992) の抵抗直列。φ→0 で平板に漸近し全開基準が連続に繋がる
- **U''(φ)**: ベース半厚み伝導と「プライム面 (1-φ)·h0 + ピンフィン増倍
  (側面積比 4φt/d × フィン効率 η ≈ 0.93)」の直列。ピン側面→流体の対流段を
  挟むため旧モデルより一桁保守的 (正直) な評価になる
- pin_fin=False 既定で旧挙動を完全温存 (回帰テストで保証)

実測 (γ スイープ、all-open は旧モデルと一致 16.2 Pa / 41.4 K):

| | ΔP [Pa] | T_peak [K] | 平均固体度 |
|---|---|---|---|
| γ=10 | 18.4 | 18.6 | 0.10 |
| γ=1 | 26.1 | 12.9 | 0.24 |
| γ=0.1 | 64.3 | 10.2 | 0.47 |
| γ=0.01 | 246.1 | 8.8 | 0.66 |

**機構の変化**: 旧モデルの固体は「流れを導く壁」(solidity ≤ 0.25、外周迂回
モチーフ) だったが、ピン版は**発熱体直上にピンを敷いて伝熱面として使い、
中央給水路だけ確保する**モチーフに変わる (γ=0.01 で solidity 0.66)。
温度が旧モデルより高いのは劣化ではなく、非物理な熱ショートカットを
取り除いた分の正直な値。

## Forchheimer 慣性補正 (forchheimer=True, run_forchheimer.py) — Task 2

∇p = -(μ/K)U - ρβ(φ)|U|U、β は Ergun 型 c_E·φ/((1-φ)³·d) (φ=0 で形状抗力
ゼロ = 平板に帰着)。面抵抗直列 1/g_eff = 1/g_D + R_F(|q|) を**緩和付き Picard**
(ω=0.5) で解く。裸の固定点は減衰振動して収束しない (実測: 40 反復で未収束、
緩和で ~20 反復に短縮)。autograd グラフを反復全体に通すので設計勾配は
FD 照合と 1e-4 で一致。返す流束は最終線形解なので発散ゼロは厳密。

実測 (Re_gap ≈ 780、ピンフィン設計の再評価):

| 設計 | ΔP_ダルシー | ΔP_D-F | 比 |
|---|---|---|---|
| all-open | 16.2 | 16.2 | 1.00 |
| γ=1 | 26.1 | 65.0 | 2.49 |
| γ=0.01 | 246.1 | 600.8 | 2.44 |

1. **慣性損失はダルシー圧損と同オーダー以上** (×2.0-2.6)。ΔP の絶対値を
   語るなら必須の補正
2. **設計もシフトする**: D-F 物理で直接最適化すると、ダルシー設計の D-F
   評価に比べ同等 T_peak で ΔP をほぼ半減 (γ=0.01: 601→312 Pa で 9.1 K 維持)。
   慣性が局所高速を罰するため、流れを長く遅い経路に分散するサーペンタイン
   状モチーフが選ばれる

## ポート位置の設計変数化 (optimize_ports, run_ports.py) — Task 3

左右エッジ全セルにガウシアン窓 (σ=2.5mm 固定) を掛け、中心 y = H·sigmoid(η)
を設計場と同時に Adam 最適化。流入はフラックス分配・流出は Robin コンダクタンス
マスクで線形性を維持し、η ごしの勾配も FD 照合済み。

実測 (ピンフィン+Forchheimer, γ∈{1, 0.1}): **中央固定が両 γ で最良**。

- 対角初期値 (in 下 10mm / out 上 70mm) からでもポートは中央 (38-45mm) へ
  自力回帰する — ネットワーク版で見えた対角カウンターフロー選好は
  **この物理では再現しない**
- ネットワーク版の対角選好は「境界一周の経路長を揃える」マニホールド構成
  だったが、連続場では設計場自身が分配を担えるため、y 対称なヒーター列に
  対して中央給水 (距離の二乗和最小) が勝つ。慣性損失もポート集中流を罰する
- ポート自由化の利得はゼロ。むしろ設計場との共進化で 3-8% 劣化する
  (free-center は非対称鞍部 57/28mm に捕捉される)

## 設計粒度の感度 (design_shape, run_granularity.py) — Task 4

「セル単位だと枝的最適解」仮説の検証。同一 48×64 セルグリッド
(margin_right=4) で設計グリッドのみ 10/5/2.5/1.25mm と細分化 (γ=1):

| 粒度 | 変数 | J | T_peak [K] | 開水路 周長/面積 |
|---|---|---|---|---|
| 10mm | 48 | 5.29 | 13.2 | 0.14 |
| 5mm | 192 | 5.10 | 12.7 | 0.33 |
| 2.5mm | 768 | 4.87 | 12.0 | 0.47 |
| 1.25mm (セル) | 3072 | 4.73 | 11.7 | 0.71 |

- 形態的には仮説どおり: 2.5mm 以下で**開水路×高密度ピン壁の交互ラメラ
  (ミニチャネルフィン列)** が出現し周長/面積比が 5 倍化
- ただし J は単調改善 (計 11%) で病的な悪化はない — ラメラは「フィン+
  チャネル」として物理的に合理的な構造
- **採用判断**: 1.25mm の縞幅は流路深さ t_chan=2mm を下回り、深さ平均
  (Hele-Shaw) 近似の妥当性スケールを外れる。概念設計は 5mm ブロックが妥当。
  細粒度の追加利得 (~1.5 K) は 3D 解像でしか信用できない

## γ 連続スイープ (run_sweep.py) — Task 5

γ を対数等間隔 15 点 (30→0.01, 降順) で継続法スイープ (初回 600 / 継続 300
反復、ウォームスタート、全 15 点 ~3 分)。妥当性: コールドスタート 4 点と
J 差 ±1% 以内 (3/4 点で warm が僅かに良い)。

- 前線は滑らかな単一トレードオフ曲線: T_peak 23.9 K (ΔP 17 Pa) → 9.0 K
  (222 Pa)、solidity 0.06→0.68 へ単調増。コントラストノブ的な同一モチーフ
  深化 (旧モデルの知見) はピンフィン物理でも大枠維持される
- 各設計を Forchheimer でも再評価: 補正は前線を右へ 1.9-2.5 倍シフト
  (γ 小ほど大)。膝は γ≈1-3 付近

  流路は半透明で上に重ねる

**注意**: torch のスレッド過剰で 20 コア機では小規模 LU が 20-30 倍遅くなる。

主要 API (v1 互換 + v2 追加):

```python
prob = make_problem(ntu_coef=1e-2)          # 4x8 発熱体、左辺ポート

r    = report(prob, cfg, x, mask)           # cooling, block_cv, leak, ...

plot(prob, cfg, x, fig, ax, mask=mask)      # 実スケール描画
```
